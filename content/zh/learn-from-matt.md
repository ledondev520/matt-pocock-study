## 从自己的问题开始

教程、工具与模型消息很多，却不一定能形成自己的开发方法。先选一个你正在遇到的卡点，再用一次小练习检验学到的方法。

Matt 从嗓音教学走向开发，公开分享涉及 XState、TypeScript 教育、AI 工程与 agent 工作流。这里关注他的思考、反馈和解释结构。

## 先关注原作者

本站向他的公开教学致敬，内容由维护者独立整理。欢迎关注 [Matt 的 X](https://x.com/mattpocockuk)、[GitHub](https://github.com/mattpocock) 与 [AI Hero](https://www.aihero.dev)。

## 选择一个入口

```cards
- **AI coding 工作流** 卡在需求、交接或验收？先把行为与验证写清楚。
- **TypeScript 基础** 不确定外部数据是否可信？从 unknown 与收窄开始。
- **写作与教学** 知道怎么做却讲不清楚？按问题、原因、方法、例子组织解释。
```

完整路线会随课程更新加入首页。目前可以先读[规格与工单](/zh/specs-and-tickets)，练习把一个想法切成可验收的小块。

```exercise
title: 给今天的学习选一个小胜利
- 写下你在项目里遇到的一个具体问题。
- 选择一个入口，列出你准备尝试的方法。
- 约定一种完成证据：能复现、能检查，或能交给同事使用。
answer: 例如把「AI 总是做错」改成「保存失败时仍显示成功」，再为失败路径写检查。
```
